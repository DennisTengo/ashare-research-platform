## 1. 项目概述

### 1.1 背景

个人做 A 股研究时会反复撞上四类问题：

1. **数据散乱**——行情在一个接口、财务在另一个、公告在第三个，每次研究都要重写抓取逻辑。
2. **数据不可信**——复权处理错误、停牌被当成零成交、财务数据用了尚未公布的报表。这些错误不会报错，只会让结论无声地反转。
3. **研究不可复现**——同一份代码今天跑出年化 15%，下周跑出 8%，因为数据更新了或代码改了一行。没有快照与版本，结论就没有意义。
4. **重复劳动**——验证第二个想法时，数据加载、收益计算、分组统计要全部重写一遍。

本项目把上述环节标准化，使得「有个想法 → 看到结果」的时间从一周压缩到一小时。

### 1.2 项目定位

**一个跑在个人电脑上、只保留「数据 + 因子 + 回测」三件事的迷你投研平台。**

它不替代聚宽、米筐等商业平台，而是用最轻的方式把这三层自己搭一遍，目的是：

- 掌握数据的完全控制权（不受第三方平台关停影响）；
- 理解回测引擎在哪些环节会误导结论；
- 形成一个可以被深度追问、每一行都能解释清楚的项目。

### 1.3 目标用户

| 用户 | 使用方式 | 关注点 |
|---|---|---|
| 项目作者（主） | 日常研究、验证想法、练习 | 效率、结果可信、可复现 |
| 面试官 / 同行（次） | 读 README、看演示、追问实现 | 架构是否合理、细节是否经得起问 |

### 1.4 非目标（明确不做）

以下内容**不在本项目范围内**，任何情况下不作为需求提出：

- 分钟级 / tick 级 / 高频数据
- 实盘交易接口、模拟交易、下单
- 多用户、权限体系、并发访问
- 期货、期权、可转债、基金、港股、美股
- 机器学习 / 深度学习的因子挖掘
- 组合优化（均值方差、风险平价）
- 移动端、App、对外部署的公网服务
- 社区、策略分享、信号发布

### 1.5 成功标准

项目完成的判定标准，按优先级：

1. 从一个新想法到看到分层收益图 ≤ 1 小时；
2. 同一数据快照 + 同一代码 → 逐位相同的结果；
3. 新增一个因子只需新增一个文件，**不修改任何核心代码**；
4. 对任一模块的实现细节，能连续回答三个「为什么」；
5. 至少用它做过三次以上真实研究，并留下记录。

## 2. 用户场景

### 场景 A：验证一个因子是否有效

> 我想知道「低波动率因子在 A 股是否有效」。

操作路径：打开平台 → 选「波动率」因子 → 选区间 2019–2025 → 选股票池「全 A 剔除 ST」→ 点击运行。

期望输出：五分组未来 20 日平均收益柱状图（应单调）、多空组合净值曲线、IC 时序图与均值 / IR。

结束条件：能说出一句有数字的结论，例如「最低波动组年化超额 4.2%，IC 均值 0.031，IR 0.28，2019 年后衰减明显」。

### 场景 B：新增一个自己想的因子

> 我想试试「近 20 日换手率的标准差」这个因子。

操作路径：在 `factor/` 下新建一个 Python 文件，实现约定的函数签名 → 重启应用 → 下拉框出现该因子 → 直接跑分层。

结束条件：写新因子的代码量 ≤ 20 行，且不需要改数据层、回测层、界面层。

### 场景 C：跑一个轮动策略

> 我想验证「每月买入动量前 20% 的股票、等权持有一个月」能不能赚钱。

操作路径：定义策略规则 → 设定成交价假设与成本参数 → 运行 → 查看净值曲线、年化、最大回撤、夏普、换手率、扣费前后对比。

结束条件：得到净值曲线的同时，也得到「这个结论值不值得信」的判断——扣费后是否还成立、换手率是否高到不可执行。

### 场景 D：数据出问题时能定位

> 平台提示某只股票在某个区间有 37 天数据缺失。

操作路径：打开数据质量页 → 查看校验失败明细 → 点进某只股票 → 查看该区间的原始数据与清洗日志。

结束条件：能判断这是停牌、退市、还是抓取失败，并触发一次补抓。

## 3. 功能需求

优先级采用 MoSCoW：**M**ust（必须）/ **S**hould（应该）/ **C**ould（可以）。

### 3.1 模块 M1：数据层

#### FR-1.1 交易日历维护 「M」
- **描述**：从数据源获取历史与未来交易日历并入库。
- **输入**：起止日期。
- **输出**：`dim_calendar` 表，字段含 `trade_date`、`is_open`、`prev_date`。
- **验收**：给定任意日期，能返回其上一个交易日与下一个交易日。
- **备注**：所有时间对齐操作的唯一基准，必须最先完成。

#### FR-1.2 股票维表维护 「M」
- **描述**：维护全部 A 股代码、名称、上市日、退市日、板块、是否 ST。
- **输入**：股票列表接口。
- **输出**：`dim_stock` 表，主键为统一格式代码（如 `600000.SH`）。
- **验收**：退市股票保留在表中（`delist_date` 非空），**不被删除**。
- **备注**：退市股保留是避免幸存者偏差的前提。

#### FR-1.3 日线行情采集（不复权）「M」
- **描述**：按股票与日期范围抓取原始价日线并入库。
- **输入**：代码列表、日期范围、模式（全量 / 增量）。
- **输出**：`fact_daily_price` 行数、失败清单、任务日志。
- **验收**：对同一区间连续执行两次增量更新，库内总行数不变（**幂等**）。
- **备注**：分批抓取（每批约 100 只），失败记录到 `meta_job_log` 供续跑。

#### FR-1.4 复权因子采集 「M」
- **描述**：采集后复权因子并单独入库。
- **输入**：代码、日期范围。
- **输出**：`fact_adj_factor` 表。
- **验收**：对任意个股，复权因子序列单调不减；前复权价由原始价与因子联合计算得到，而非直接入库。
- **备注**：**库中永不存储前复权价格**，这是保证历史研究可复现的核心约束。

#### FR-1.5 财务数据采集（PIT 对齐）「S」
- **描述**：采集利润表、资产负债表、现金流量表关键科目。
- **输入**：报告期列表。
- **输出**：`fact_financial` 表，主键 `(code, report_period, announce_date)`。
- **验收**：任意查询「某日可知的最新财报」时，只返回 `announce_date <= 该日` 的记录。
- **备注**：公告日必须进入主键，否则后续任何财务因子都会引入未来函数。

#### FR-1.6 数据质量校验 「M」
- **描述**：对入库数据执行规则化检查，输出问题清单。
- **校验规则（最小集）**：
  1. 单日涨跌幅超过限制（主板 ±10%、创业板/科创板 ±20%、ST ±5%，考虑新股与除权日）；
  2. 收盘价或成交量为空、为负；
  3. 同一 `(code, trade_date)` 重复；
  4. 交易日历内出现连续断档超过 N 日；
  5. 复权因子非单调；
  6. 成交量为 0 但价格发生变化。
- **输出**：`meta_dq_result` 表 + 页面展示。
- **验收**：每条规则配一个 pytest 用例，用手工构造的异常数据触发。

#### FR-1.7 任务日志与断点续跑 「M」
- **描述**：记录每次采集任务的批次、标的范围、开始结束时间、成功失败条数、错误摘要。
- **输出**：`meta_job_log` 表。
- **验收**：任务中断后重新执行，已成功的批次不重复抓取。

### 3.2 模块 M2：数据概览

#### FR-2.1 覆盖看板 「M」
- **描述**：首页展示数据健康度。
- **内容**：股票总数、在市区间的起止日期、最新数据日期、交易日覆盖率、当日新增行数、上次更新时间。
- **验收**：打开首页 3 秒内加载完成，数据明显过期时（如最新日期落后交易日超过 3 天）给出醒目提示。

#### FR-2.2 校验结果页 「S」
- **描述**：列出最近一次校验的问题明细，可按规则类型与股票筛选。
- **验收**：点击单条可跳转到该股票的原始数据视图。

### 3.3 模块 M3：个股查询

#### FR-3.1 K 线与成交量 「M」
- **描述**：输入代码，展示指定区间的 K 线与成交量。
- **交互**：支持区间切换（1M / 6M / 1Y / 3Y / 自定义），支持前复权 / 后复权 / 不复权切换。
- **验收**：切换复权方式时，K 线形态与价格同步变化，最高最低价与数据源核对一致。

#### FR-3.2 复权因子曲线 「C」
- **描述**：展示该股票的复权因子时序，标记除权除息日。
- **价值**：直观看出数据是否被正确复权。

#### FR-3.3 财务指标表 「S」
- **描述**：按报告期列出营收、净利润、毛利率、ROE、资产负债率等。
- **验收**：任一报告期的数值可追溯到其公告日；页面标明「该期数据于 X 日可知」。

#### FR-3.4 基本信息卡 「C」
- **描述**：名称、代码、板块、上市日、所属行业、是否 ST / 退市。

### 3.4 模块 M4：因子分析

#### FR-4.1 因子清单与参数 「M」
- **描述**：下拉列出所有已注册因子，可设置参数（如窗口长度）与股票池（全 A / 沪深 300 / 中证 500 / 剔除 ST / 剔除次新）。
- **验收**：新增因子文件后无需改代码，重启即出现在清单中。

#### FR-4.2 分层收益 「M」
- **描述**：按因子值横截面排序分五组（或多组），计算各组未来 N 日平均收益。
- **输出**：分组柱状图 + 明细表（每组的均值、中位数、样本数、t 值）。
- **验收**：用手工构造的 20 只股票、2 个交易日的迷你数据集验证，结果与手工计算一致。

#### FR-4.3 多空组合净值 「M」
- **描述**：做多最高组、做空最低组（或仅多头），输出累计净值曲线。
- **输出**：净值曲线、年化收益、最大回撤、夏普、月度胜率。
- **验收**：与分层收益的方向一致；若不一致则界面给出提示。

#### FR-4.4 IC 分析 「M」
- **描述**：计算因子值与未来收益的横截面秩相关系数序列。
- **输出**：IC 时序图、IC 均值、IC 标准差、IR、IC>0 占比、IC 衰减曲线（1/5/10/20 日）。
- **验收**：IC 均值与分层收益的方向一致。

#### FR-4.5 因子间相关性 「C」
- **描述**：多选因子，输出相关性矩阵热力图。
- **价值**：判断新因子是否只是已有因子的变体。

#### FR-4.6 结果导出 「C」
- **描述**：将当前分析的图表与明细表导出为 CSV / PNG。

### 3.5 模块 M5：因子扩展

#### FR-5.1 因子函数规范 「M」
- **描述**：定义统一的因子接口，输入为价格 / 财务数据对象与参数，输出为「日期 × 股票」的因子值矩阵。
- **约束**：因子函数**不得**直接访问数据库或网络，只能使用传入的数据对象。
- **价值**：保证可测试性与可复现性。

#### FR-5.2 自动注册 「M」
- **描述**：将因子文件放入约定目录即被自动发现，无需手动注册。
- **验收**：新增文件后重启，因子出现在下拉框中；文件有语法错误时给出清晰提示而非整个应用崩溃。

#### FR-5.3 因子元信息 「S」
- **描述**：每个因子声明名称、描述、参数默认值、方向（越大越好 / 越小越好）、作者备注。
- **价值**：页面直接展示，也让 README 能自动生成因子清单。

### 3.6 模块 M6：回测

#### FR-6.1 策略定义接口 「M」
- **描述**：策略以函数形式定义，输入历史数据与当前日期，输出目标持仓权重。
- **约束**：策略函数只能看到 `<= 当前日期` 的数据（由框架保证，不依赖使用者自觉）。

#### FR-6.2 成交假设 「M」
- **描述**：信号在 T 日收盘后生成，T+1 开盘价成交；强制对信号做一格滞后。
- **验收**：故意写一个「用当日收盘价成交」的错误配置，框架应拒绝执行或明确警告。

#### FR-6.3 可交易性约束 「M」
- **描述**：停牌（成交量为 0）、涨停、跌停的股票不可成交，持仓顺延。
- **验收**：构造一个「买入次日涨停股」的用例，验证该笔交易未成交。

#### FR-6.4 成本模型 「M」
- **描述**：佣金（双边）、印花税（卖出）、滑点三项可配置，默认值写在配置文件中并在界面显示。
- **验收**：将成本参数从 0 调至默认值，同一策略的年化收益显著下降；参数改动会改变结果。

#### FR-6.5 绩效指标 「M」
- **描述**：年化收益、累计收益、最大回撤、夏普、卡玛、胜率、换手率、扣费前后对比、相对基准超额。
- **验收**：所有指标可由净值序列独立复算验证。

#### FR-6.6 持仓与交易明细 「S」
- **描述**：可查询任意日期的持仓明细与当日交易清单。

#### FR-6.7 框架自检（随机因子测试）「M」
- **描述**：用随机信号跑完整回测流程，检验框架是否产生虚假收益。
- **验收**：多次随机试验的净值应围绕 0 波动，扣费后均值为负；若出现显著正收益，判定框架存在缺陷。
- **价值**：这是回测模块可信度的唯一来源，也是面试时最有说服力的一句话。

### 3.7 模块 M7：系统与工程

#### FR-7.1 配置管理 「M」
- 数据路径、数据库路径、成本参数、股票池定义统一在配置文件中，代码中不出现硬编码路径与密钥。

#### FR-7.2 日志 「M」
- 分级日志（INFO / WARNING / ERROR），采集任务与回测运行分别落文件。

#### FR-7.3 一键启动 「M」
- 单条命令完成「环境检查 → 数据增量更新 → 启动界面」。

#### FR-7.4 可复现运行 「S」
- 每次回测记录：代码版本（git commit）、数据快照日期、参数、随机种子、结果摘要。

#### FR-7.5 单元测试 「M」
- 覆盖：数据校验规则、复权计算、收益计算、因子计算、成本计算。
- 验收：`pytest` 全部通过；测试不依赖网络。

#### FR-7.6 容器化 「C」
- 提供 Dockerfile，一条命令在任意机器启动。

## 4. 数据需求

### 4.1 数据范围

| 项 | 范围 |
|---|---|
| 标的 | 全部 A 股（含退市，用于回测期存活样本） |
| 频率 | 日频 |
| 历史长度 | 建议 2015 年至今（可按需缩短以降低首次抓取成本） |
| 规模估算 | 约 5,400 只 × 2,600 交易日 ≈ 1,400 万行，DuckDB 存储约数百 MB |
| 品种 | 仅股票，不含基金、债券、期货、期权 |

### 4.2 核心表

| 表名 | 说明 | 主键 |
|---|---|---|
| `dim_calendar` | 交易日历 | `trade_date` |
| `dim_stock` | 股票维表（含退市） | `code` |
| `fact_daily_price` | 不复权日行情 | `(code, trade_date)` |
| `fact_adj_factor` | 复权因子 | `(code, trade_date)` |
| `fact_financial` | 财务数据（PIT） | `(code, report_period, announce_date)` |
| `fact_factor` | 因子值 | `(factor_name, trade_date, code)` |
| `meta_job_log` | 采集任务日志 | 自增 |
| `meta_dq_result` | 数据校验结果 | 自增 |

### 4.3 数据源策略

- **主源**：akshare（覆盖行情、财务、日历，免费）。
- **校验源**：baostock（同一区间抽样比对，差异超阈值报警）。
- **降级源**：本地行情客户端（主源失效时的手工兜底）。
- **原则**：任何单一数据源失效都不得导致平台完全不可用；失败必须被记录而非静默。

### 4.4 数据约束（硬性）

1. 库中只存不复权价 + 复权因子，**不存前复权价**。
2. 财务数据必须带公告日，查询接口默认只能看到已公告数据。
3. 原始层（staging）数据只增不改，清洗逻辑变更时从原始层重跑。
4. 股票代码统一格式，入库前做标准化。
5. 所有金额字段标注单位并在文档中固定。

## 5. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 可复现性 | 相同数据快照 + 相同代码 → 输出逐位一致 |
| NFR-2 | 性能 | 全市场 5 年日线，单因子分层计算 < 30 秒；页面交互 < 3 秒 |
| NFR-3 | 可扩展性 | 新增因子不修改核心代码；新增策略不修改数据层 |
| NFR-4 | 可移植性 | 仅依赖 Python 与少量第三方库；可选 Docker 一键启动 |
| NFR-5 | 健壮性 | 外部接口全部具备超时、重试、降级；任一接口失败不导致数据损坏 |
| NFR-6 | 可测试性 | 核心计算逻辑单测覆盖；测试不依赖网络 |
| NFR-7 | 可解释性 | 任意一个数字都能追溯到「哪张表、哪段代码、哪个假设」 |

## 6. 技术约束

| 层 | 选型 | 约束说明 |
|---|---|---|
| 语言 | Python 3.11 | 避免过新版本的数据生态兼容问题 |
| 数据处理 | pandas + numpy | 向量化优先，禁止逐行循环处理全市场 |
| 存储 | DuckDB | 单文件、列式、零部署；**写标准 SQL**，不依赖方言 |
| 界面 | Streamlit | 纯 Python，不引入前端工程 |
| 图表 | plotly | 交互式，Streamlit 原生支持 |
| 测试 | pytest | 只测计算与校验逻辑 |
| 依赖管理 | uv | 锁定版本，保证可复现 |
