记录开发中遇到的问题、被否决的方案、以及每个可用状态的代码位置。
用途有三个：复盘、避免重复踩同一个坑、必要时回退。

- **查历史问题**：看下面的「问题索引」

### 回退操作

```bash
git log --oneline            # 看历史
git tag -l                   # 看里程碑

# 只看某个版本，不改当前工作区
git checkout v0.2-basic-data

# 把工作区恢复到某个版本（会丢弃之后的改动，慎用）
git reset --hard v0.2-basic-data

# 撤销某次提交但保留历史（推荐用于已推送的提交）
git revert <commit>

# 只恢复某个文件到某个版本
git checkout v0.2-basic-data -- collector/daily_price.py
```

**注意：`data/` 目录不在版本控制里。** 回退代码后，数据库仍是回退前的状态。
如果改了表结构或因子算法，回退后需要清空对应表并重新同步数据。

## 详细记录

### 001 虚拟环境创建失败

- **现象**：`python -m venv .venv` 报 `ensurepip` 失败，建出来的环境没有 pip。
- **根因**：系统 Python 安装缺 ensurepip 的 bundled wheel；同时沙箱限制临时目录写入。
- **方案**：先用 `python -m pip install virtualenv`，再 `python -m virtualenv .venv`。
  需要非沙箱权限执行，否则 pip 写临时文件会被拒。
- **结果**：Python 3.14.8 + pip 26.2.2。依赖全部安装成功。
- **遗留问题**：装的是 pandas 3.0，与网上大量 1.x/2.x 教程存在 API 差异
  （`inplace` 部分用法、字符串 dtype 推断）。跟教程写代码报错时先怀疑版本，不是代码写错。
- **回退点**：`05b104f`

### 002 pytest 缓存写入被拒

- **现象**：测试能跑，但每次输出 `PytestCacheWarning: could not create cache path`。
- **根因**：沙箱不允许 pytest 在工作区创建 `.pytest_cache` 临时目录。
- **方案**：`pyproject.toml` 里加 `-p no:cacheprovider`，直接关掉缓存插件。
- **代价**：`pytest --lf`（只跑上次失败的用例）不可用。个人项目可接受。
- **回退点**：`6754b79`

### 003 股票代码 302132 无法识别，整批中断

- **现象**：采集股票列表时抛 `ValueError: 无法识别的代码前缀: '302132'`，整批数据都没入库。
- **根因**：`infer_a_share_exchange` 用的是**前缀枚举**（600/601/300/301...），
  交易所新增号段（创业板 302）时必然漏掉。
- **方案**：
  1. 改为**首位归类**（6→SH、0/3→SZ、4/8→BJ、92/93→BJ），新号段自动覆盖；
  2. 单只代码识别失败时返回 `None` 并记警告，不打断整批。
- **教训**：凡是"枚举外部系统取值"的代码，都要假设它会扩充。能按规则归类的不要枚举。
- **回退点**：`c73409f`

### 004 最新交易日返回未来日期

- **现象**：`latest_trade_date()` 返回 `2026-12-31`，而当天是 `2026-10-21`。
- **根因**：交易所日历接口返回的是**含已排定的未来交易日**的完整日历，
  直接取 `max(trade_date)` 会拿到未来的日期。
- **方案**：查询加 `trade_date <= 当前日期` 上界，并提供 `as_of` 参数支持回看历史某天的状态。
- **影响面**：所有"最新数据日期"的判断都会错，包括增量同步的起点计算。
- **回退点**：`c73409f`

### 005 东财历史 K 线端点不可用

- **现象**：`akshare.stock_zh_a_hist` 稳定报 `RemoteDisconnected`，重试 3 次全失败。
- **诊断过程**（这组对照实验值得保留）：

  | 测试 | 结果 |

  | `www.baidu.com` | 200 |
  | `quote.eastmoney.com`（东财主站） | 200 |
  | `push2.eastmoney.com`（东财实时行情） | 200 |

  还排除了：DNS 解析正常、443 端口可连、无代理配置、加速器无关（只加速 Steam/GitHub）。
  试过 `ut` token 与浏览器 User-Agent 的四种组合，均失败。
- **结论**：仅 `push2his` 这一个服务端点在当前出口不可用，客户端无法进一步定位。
- **方案**：行情主源切 `baostock`，`akshare` 保留为备源（`--source akshare` 可切回）。
- **教训**：免费数据源必须双源并存。任何单一源失效都不能让整条链路停摆。
- **回退点**：`9390a82`

### 006 两个数据源成交量单位差 100 倍

- **现象**：同一只股票同一天，akshare 返回 32156，baostock 返回 3215644。
- **根因**：akshare 的成交量单位是**手**（1 手 = 100 股），baostock 是**股**。
- **验证方法**：用 `成交额 ÷ 成交量` 反推均价，看是否落在当日 `low ~ high` 区间内。
  茅台 32156 手 × 100 × 1685 ≈ 54.2 亿，与成交额 54.4 亿吻合，确认是手。
- **方案**：适配层 `sources.py` 明确处理差异，akshare 分支 ×100，baostock 分支不动，
  统一输出「股」。并有测试锁住这个约定。
- **如果搞错的后果**：成交额放大 100 倍、换手率全错，而且**不会报错**，只会让结论悄悄偏掉。
- **回退点**：`9390a82`

### 007 复权因子算法 v1：因子每天变化 ❌

- **方案**：`复权因子 = 后复权收盘 / 不复权收盘`
- **现象**：因子从 2.47 一路涨到 135.9，每天都在变，不是阶梯函数。
- **根因**：数据源的"后复权价"是按**涨跌幅复权**累计出来的，
  两者相除得到的是"复权价与原始价的比值"，而不是"除权调整倍数"。
- **结论**：否决。这个公式看似合理，实际不成立。
- **教训**：涉及"复权"的字段，必须先验证它是不是阶梯函数，再决定能不能直接用。

### 008 复权因子算法 v2：真实分红被误杀 ❌

- **方案**：v1 改成收益率累乘（已正确），再叠加一条"数据源不连续检测"：
  若原始价正常（±21% 内）但比值偏离 1 超过 0.5%，判定为异常并置 1。
- **现象**：所有因子全部变成恒等于 1.0，真实分红被一并修掉了。
- **根因**：**现金分红只让原始价跌 1~3%**，完全落在正常波动区间内，
  用"比值是否突变"根本区分不了"真实除权"和"数据故障"。
- **结论**：否决。
- **教训（重要）**：区分这两种情况要看**复权价自身的单日变化**，不是看两者比值。
  - 真实除权：原始价跳（分红送股），复权价连续
  - 数据故障：复权价大幅跳变，原始价正常

### 009 复权因子算法 v3：采用 ✅

- **算法**：逐日 `复权收益率 ÷ 原始收益率` 累乘，叠加两道保护：
  1. 数据源不连续检测：复权价单日变化超出 `[-15%, +100%]` 且原始价正常 → 比值置 1
  2. 单调性硬约束：比值小于 1（因子下降）→ 置 1（真实除权只会让因子上升）
- **验证**：5 只股票、各 1646 个交易日，38 次跳升全部为正，0 次下降，
  因子范围 1.0 ~ 1.35，跳升日与分红除权日一一对应。
- **已知限制**：因子以**拉取起点**为基准（2020-01-02 = 1.0），只保证比率正确。
  因此**增量更新不能只拉新增区间**，必须从固定起点重算，否则新旧基准不一致。
- **回退点**：`9390a82`

### 010 baostock 长连接中断导致整批失败

- **现象**：300 只同步到 143 只后，后续每只都报“网络接收错误”，连续失败 62 只，数据停在 229649 行。
- **根因（两层）**：
  1. **直接诱因**：电脑息屏后网卡进入低功耗，TCP 长连接被断开（用户侧确认）。
  2. **代码缺陷（真正放大后果的）**：`_logged_in` 是一个全局标志，一旦置 True 就永不重置。
     连接断了标志仍是 True，`_ensure_baostock_login` 直接返回，后面每只都拿失效连接查询，必然全败。
- **方案**：`fetch_baostock` 捕获异常后判断是否为网络类错误（匹配“网络/接收/连接/超时”等文案），
  是则调 `_force_relogin()`（先置 False → logout → 重新 login）再重试**一次**。
  只重试一次，避免真故障时无限递归。
- **验证**：修复后续跑 152 只，失败 0，不再中断。
- **教训**：长连接类数据源必须有自愈能力。“已登录”标志只能说明“曾经登录成功”，不能证明连接当前可用。
  推而广之，任何依赖外部会话状态的标志位，都要设计成可失效、可重建。
- **附带处理**：可关闭 Windows 网卡省电（`powercfg /change monitor-timeout-ac 0`）避免息屏断连。
- **回退点**：后续提交

### 011 涨跌幅校验：必须用复权价

- **现象**：用原始价检查“单日涨跌幅超限”，300 只股票报出 **119 条**，几乎全是高送转股票。
- **根因**：除权日原始价跳空（10 送 10 直接腰斩）、这是真实市场行为，不是数据错误。
- **方案**：
  1. 用 **复权价**（`close × adj_factor`）算收益率，除权日复权价是连续的；
  2. 阈值按板块：主板 10%、双创 20%、北交所 30%、ST 5%，各加 1.5% 容差；
  3. 跳过每只股票前 5 个交易日（全面注册制下新股上市前 5 日不设涨跌幅）。
- **验证**：119 条 → 4 条 → 1 条。剩下的 000792.SZ（盐湖股份 2021-08-10 恢复上市首日 +306%）
  是暂停上市一年多后复牌的真实行情，不是错误。
- **教训**：**任何跨除权日的收益率计算，都必须先复权**。同样的错误在因子、回测、分组排序里都会重现。
- **回退点**：后续提交

### 012 停牌期间除权造成的假“价格变动”

- **现象**：600027.SH 2024-07-25 成交量为 0，但“零成交但价格变动”规则报异常，而打印出来的复权价都是 7.4561。
- **根因**：停牌期间发生分红除权，原始价 6.08 → 5.93、因子 1.2263 → 1.2574 同步调整，
  复权价理论不变，但价格只保留两位小数，乘上因子后产生 **5e-5** 的相对误差，超过原定的 1e-6 绝对阈值。
- **方案**：判据从绝对误差改为**相对误差**（1e-4）。
- **教训**：比较经过多步浮点运算的值，用相对误差，不用绝对误差。
- **回退点**：后续提交

### 013 因子框架：因子只算数，其余交给引擎

- **设计原则**：一个因子只做一件事——给一段日线（含 `adj_close`），返回同长度的一列数。
  不碰数据库、不处理停牌、不管有多少只股票。这些共性麻烦全部提到引擎层。
- **协议**：`Factor(name, description, lookback, fn)`，注册时重名直接报错。
  新增因子 = 写一个函数 + 一行 register + 在 `factors/__init__.py` 加一行导入。
- **引擎职责**：统一算复权价（`close × adj_factor`）、按股票分组、过滤建仓期 NaN、先删后插保证幂等。
- **首批因子**：`momentum_20d`、`reversal_20d`、`volatility_20d`。
  同时放反转和动量是为了自检：两者必须严格互为相反数，一旦不成立就是链路搞反了。
- **验证**：
  - 77 个测试通过；
  - 3 因子 × 300 只 = 1,407,690 行；
  - 动量与反转 0 行不匹配，方向确认无误；
  - 波动率均值 2.31%（日），符合 A 股量级；
  - 000001.SZ 2024-01-15 动量恰为 0，核对复权价确实相同（2023-12-15 与 2024-01-15 均为 9.21），
    是巧合而非计算错误。
- **新发现的问题（待处理）**：新股上市初期会产生极端值。
  603392.SH（万泰生物，2020-04-29 上市）在 2020-06-01 的 20 日动量高达 **573%**，
  因为窗口覆盖了上市初期的连续一字涨停。分组时这类值会占据极端组，需要设置上市天数门槛或去极值。
- **教训**：因子函数只占工作量的一小部分，真正的工作在对齐、边界、幂等和方向自检。
- **回退点**：后续提交

### 014 分组回测：重叠收益当单日收益年化，虚高 20 倍

- **现象**：第一版报告各组年化 **5205% ~ 7560%**，年化波动 105%；多空累计收益 -70%，
  却同时报年化 +45%，自相矛盾。
- **根因**：每天算一个“未来 20 日持有收益”，再把这个数当成“单日收益”乘 252 次年化。
  两层错误叠在一起：① 时间被放大 20 倍；② 相邻样本共享 19 天，自相关极强，夏普严重失真。
- **方案**：改为**不重叠调仓**——每 20 个交易日只取一个调仓日，年化按 252/20≈12 期计算。
- **结果**：各组年化回到 14% ~ 34%，波动 19% ~ 33%，多空累计与年化方向一致。
- **教训**：**任何“持有 H 天的收益”都不能按日频年化**。要么不重叠调仓，要么按 H 折算期数。
  这条在后续任何周期的回测里都会重现。
- **回退点**：后续提交

### 015 三个因子的实测结论（沪深300 / 2020-04 ~ 2026-09 / 79 期）

| 因子 | 多空年化 | 夏普 | 胜率 | 单调 | 结论 |
|---|---|---|---|---|---|
| `momentum_20d` | -1.51% | -0.06 | 49.4% | 否 | 无效，呈 U 型 |
| `reversal_20d` | +0.95% | 0.04 | 49.4% | 否 | 无效，呈 U 型 |
| `volatility_20d` | +16.82% | 0.57 | 53.2% | 近似单调 | **有效** |

- **动量与反转均无效**：两者多空收益几乎为零且方向相反，说明 20 日尺度上的
  涨跌幅对未来 20 日收益没有预测力。这与“A 股短期反转效应”的常见说法不符，
  可能因为样本是沪深300 大盘股，而反转效应主要在小盘股上。
- **动量的 U 型值得注意**：G1（跌得最多）27.3%、G5（涨得最多）25.4%，中间组只有 14.5%。
  两端都高，且两端的波动也明显更高（25% / 26% vs 19%）。
  推测这不是动量效应，而是**波动率混淆**：动量绝对值大的股票 ≈ 高波动股票。
- **波动率因子显著**：G1（低波）14.8% → G5（高波）33.9%，多空累计 +99.7%。
  方向与“低波动异象”相反 —— 这六年沪深300 里高波动股票反而跑赢。
  但高波动组年化波动 33.2%，夏普 1.02 与低波组 0.96 相差不大，
  并不是“免费午餐”，而是承担更多风险换更高收益。
- **待验证**：按波动率分组后再看动量是否还有预测力（波动率中性化）。
  如果中性化后动量彻底消失，就能确认 U 型完全由波动率驱动。
- **回退点**：后续提交

### 016 波动率中性化：U 型确认是混淆，但中波动层出现反转

- **方法**：每个调仓日先按 `volatility_20d` 分 3 层，再在各层内按 `momentum_20d` 分 5 组。
- **结果**：

  | 层 | 多空年化 | 夏普 | 单调 |
  |---|---|---|---|
  | 第 1 层（低波） | +8.20% | 0.43 | 否 |
  | 第 2 层（中波） | **-11.68%** | -0.61 | **是（递减）** |
  | 第 3 层（高波） | +7.64% | 0.23 | 否 |

- **解读**：
  1. 原来分组报告里的 U 型**确实是波动率驱动**——控制波动率后不再出现两端跑赢。
  2. 但中波动层出现了**显著的反转效应**：G1（跌最多）24.89% → G5（涨最多）10.54%，
     严格递减，多空 -11.68%。这是三层中唯一单调的一层。
  3. 推测机理：低波动股票涨跌幅本身幅度小，信号被压制；高波动股票受情绪驱动、方向无序；
     **中波动是反转最容易显现的区间**。
- **局限**：每层 100 只、每组 20 只、79 期，样本量有限；只做了 3 层切分，未做稳健性检验。
  单层的 -11.68% 需要换层数（4 层/5 层）、换时间段重跑确认，才能当作结论。
- **教训**：一个因子“无效”和“在特定条件下有效”是两回事。
  控制混淆变量后，原本不显著的效应可能浮现——反之亦然。单层回测只能给出笼统印象。
- **回退点**：后续提交

### 017 IC 分析与分组收益矛盾，揭示波动率因子不稳定

- **实现**：`analysis/ic.py`。每期算因子排名与未来收益排名的秩相关，汇总均值/ICIR/胜率/t 值。
  依赖问题：pandas 的 `method="spearman"` 内部调 scipy，而项目没装 scipy。
  解决：先 rank 再算 Pearson，数学上完全等价，不引入新依赖。
- **结果（持有 20 日，79 期）**：

  | 因子 | IC 均值 | ICIR | 胜率 | t 值 |
  |---|---|---|---|---|
  | `momentum_20d` | -0.0251 | -0.12 | 48.1% | -1.08 |
  | `reversal_20d` | +0.0251 | +0.12 | 51.9% | +1.08 |
  | `volatility_20d` | -0.0282 | -0.11 | 43.0% | -0.94 |

- **关键矛盾**：波动率的 IC 是 **负的**（-0.028），但分组回测显示多空 **+16.82%**（高波动组跑赢）。
- **原因**：
  1. IC 是“每期相关系数的平均”，分组回测是“每期分组均值的平均”，两者数学上不等价；
  2. 波动率 IC 标准差高达 0.2665，胜率仅 43%——意味着 **57% 的期数里高波动跑输**，
     靠少数几期大幅跑赢把均值拉高；
  3. 结论：波动率因子的收益**依赖少数行情**，不是持续稳定的关系。
- **教训**：**只看分组多空会高估因子稳定性**。分组法把 79 期压成 5 个数，看不到逐期波动；
  IC 序列保留了时间维度，能看出“平均赚”和“每期都赚”的区别。这正是 IC 相对分组法的核心价值。
- **另一个结论**：三个因子 |t| 均 < 2，**统计上都不显著**。样本只有 79 期，统计效力有限。
- **回退点**：后续提交

### 018 组合回测：扣掉成本后因子全部不赚钱

- **成本假设**：买入 0.13%（佣金万三 + 滑点），卖出 0.23%（再加印花税千一）。
- **动量因子**（80 期）：

  | 组合 | 年化 | 夏普 | 最大回撤 | 平均换手 |
  |---|---|---|---|---|
  | 基准（等权全市场） | 18.74% | **0.92** | -19.85% | 1.5% |
  | G5 | 17.26% | 0.66 | -37.26% | 76.1% |
  | 多空（毛） | -4.32% | -0.18 | -63.76% | 78.6% |
  | 多空（净） | -11.16% | -0.46 | -72.05% | 78.6% |

- **波动率因子**：基准相同；G5 年化 24.72%、夏普 0.75、回撤 -31.82%；
  多空毛 12.06%（夏普 0.41）→ 净 7.68%（夏普 0.26），成本拖累 4.38%。
- **三个关键发现**：
  1. **基准的夏普（0.92）高于所有单组**。无论动量还是波动率，分五组后每组都不如
     直接等权买下全部 300 只。原因：分组把持仓从 300 只压缩到 60 只，牺牲了分散化收益。
  2. **换手率极高**：动量 76%~81%，波动率 43%~70%。因为 20 日尺度的因子本身变化很快，
     每期都会换掉大部分持仓。成本拖累 4.4%~6.9%。
  3. **扣成本后多空：动量 -11.16%，波动率 +7.68%（夏普仅 0.26）**。
- **教训**：**分组回测是研究视角，组合回测是实盘视角**。
  前者问“因子有没有区分度”，后者问“交易它能不能赚钱”。两者差距主要来自：
  分散化损失、换手成本、以及分组后样本变小带来的噪声放大。
- **这不是失败**：能定量拆解出“为什么不可行”，比“找到一个回测很漂亮的因子”更有价值。
  回测漂亮的因子十有八九是未来函数或数据挖掘的产物。
- **回退点**：后续提交

### 019 财务数据：按公告日对齐，不是报告期

- **问题**：财报有两个日期——报告期（statDate）和公告日（pubDate）。实测 5 只股票 130 期数据，
  两者相差 **19~121 天，平均 48 天**。如果用报告期对齐行情，等于提前一个半月知道财报结果。
- **方案**：
  1. 入库同时保留两个日期，主键 `(code, report_period, announce_date)`——
     同一报告期可能多次公告（快报/更正），每次都要留痕；
  2. 对外查询用 DuckDB 的 `ASOF JOIN` 按公告日对齐：`p.trade_date >= f.announce_date`。
- **验证**：
  - 2024-04-15 → 只能看到 2023 年报（2024-03-15 公告）
  - 2024-04-30 → 才能看到 2024 一季报（2024-04-20 公告）
  - 写成单测 `test_asof_join_respects_announce_date`，以后改对齐逻辑会立刻报错。
- **为什么不分表**：利润表、资产负债表、成长性三张表的公告日可能不同步，
  分表后 asof 对齐会各落各的期次，分子分母可能不同期（如 2024Q1 净利润 ÷ 2023 年末净资产），
  错误极其隐蔽。单表一次对齐，没有这个问题。
- **已知缺口**：
  - `revenue` 在 Q1/Q3 为空——baostock 只在半年报和年报提供 MBRevenue；
  - `total_assets` / `total_equity` 无法从 baostock 获取（只有资产负债率与权益乘数），
    需要后续用 akshare 资产负债表补充。
- **教训**：**财务数据的对齐锚点必须是公告日**。这一条比任何因子设计都重要，
  因为错了不会报错，只会让所有回测莫名变好。
- **回退点**：后续提交

### 020 财务数据全量完成：7676 行，四个疑点逐一核实

- **结果**：300 只 × 2020Q1~2026Q2（26 期）= 7676 行，公告日 100% 有值，
  耗时 73 分钟，零失败。
- **期数不是缺失**：按年报 26 期就是满的。263 只 26 期（满）、15 只 27 期（多了刚披的 2026Q3）、
  22 只少于 26 期（2020 年后上市的次新股）。
- **四个疑似异常逐一核实**：
  1. **公告滞后 8~12 天**：业绩快报日。如 600415 在 2025-04-08 发快报，正式报告晚两周。
     快报本身是公开信息，不算前视，但比正式公告早，数据上偏乐观。
  2. **公告滞后 200~485 天**：全是次新股（688271、688041、603296 等），
     2021Q1 财报是 2022 年上市时在招股书里补披露的。这不是错误，
     而是 PIT 对齐在正确工作——它们在上市当天才进入可见范围。
  3. **ROE -601%**：海航控股 2022H1，净利 -136 亿，净资产近零，分母太小把比率放大到无意义。
  4. **净利率 68.8%**：国投资本这类券商，营收口径含投资收益，与制造业不可比。
- **对因子层的两个硬约束**（写财务因子时必须处理，否则回测会失真）：
  1. **负净资产股要剔除或截尾**：ROE 分母接近零时会出现 ±600% 这类数值，
     不处理会把分组排序完全打乱。
  2. **金融股口径不同**：银行/券商/保险的营收、毛利率、净利率与制造业不可比，
     同一因子混排等于把两类东西放一个尺子上量。至少要做行业内分组，或单独剔除。
- **已知缺口**：`revenue` 在 Q1/Q3 缺失 51.4%（baostock 只在半年报/年报提供），
  `gross_margin` 缺失 15.8%（部分股票不给），
  `total_assets` / `total_equity` 仍为空，需 akshare 补。
- **回退点**：后续提交

### 021 财务因子：累计口径必须先年化

- **陷阱**：baostock 的 `roeAvg` 是**年内累计口径**——Q1 是一季度 ROE，Q4 是全年 ROE。
  直接拿来做因子，每年 4 月一季报一出，所有股票 ROE 集体“跳水”四分之三。
  这不是公司变差，是统计口径变了，但因子会当成真信号。
- **处理**：按季度数年化（Q1×4、H1×2、前三季×4/3、年报×1）。
- **验证**：年化后各月均值 11.6%~13.4%，最大差 15%（剩余差异来自利润前低后高的季节分布，
  可接受）；不年化的话 4 月会从 13% 掉到 3% 左右。
- **同比的分母问题**：净利润同比在去年同期为负时无法用百分比表达（负转正、亏损收窄都是“增长”），
  直接算会得到 -200% 这类误导值。选择置空而不是硬算，代价是亏损股的年报期次无值。
- **因子协议扩展**：`Factor` 加 `requires` 字段声明所需财务列，引擎汇总后一次合并，
  避免每个因子各查一遍库。价格因子 `requires` 为空，行为完全不变。
- **分层**：对齐、年化、同比全部在 `analysis/financial.py`，因子函数只做取值和截尾。
  理由是这些都是财务语义判断，不属于“排序算法”。
- **暂缓的因子**：净利率类。金融股（银行/券商/保险）的营收口径含投资收益，
  与制造业不可比，横截面混排等于用两种刻度尺量东西。需要行业分类数据才能做。
- **横截面分布**：ROE 中位 11.1%、p25 6.6%、p75 17.5%，逐年均值 10.9%/14.1%/14.4%/12.4%/11.5%，
  与 2021-2022 周期高点、2023 后回落一致。
- **实测结果（沪深300，20 日调仓，78 期）**：ROE 的 IC -0.0091（t -0.56，胜率 50.0%），
  净利润同比的 IC -0.0106（t -0.51，胜率 43.6%），分组收益均不单调。
  与三个价格因子一样不显著——**功能链路已验证跑通，因子本身没有区分能力**。
  不调参数去凑结果：财务信息释放慢，20 日窗口本就难以捕捉，这是结论不是缺陷。
- **回退点**：后续提交

### 022 界面：四页 Streamlit，统计全部复用 pipeline

- **页面**：数据概览（FR-2.1）、个股查询（FR-3.1/3.3/3.4）、因子分析（FR-4.1~4.4）、
  数据校验（FR-2.2），加 `run.py` 一键启动（FR-7.3）。
- **复权换算放界面层，不改库**：库里只有原始价与因子，切前复权时实时乘。
  前复权以「区间最后一日」为基准，所以历史价格会随区间变化——
  这是前复权的定义，不是 bug，页面上已写明。
- **界面不自己算统计**：分层收益、IC、绩效全部调 `analysis.pipeline`，
  与命令行、测试、存档共用一套口径，避免「界面 5.2%、脚本 4.8%」这类分叉。
- **踩到的坑：Streamlit 首次启动会弹交互式邮箱询问**，子进程里无人应答就永远卡住。
  表现为「打印完启动行就没下文」，但进程活着、端口不通。
  修法：显式传 `--server.headless=true` 并设环境变量。
  教训：健康检查必须看 HTTP 200，不能看「进程是否存活」。
- **测试**：新增 5 个 `AppTest` 界面冒烟用例（149 个全部通过）。
  价值在于以后改数据层时，空结果或字段改名会让页面在测试里直接爆掉，
  而不是等用户点开才发现白屏。
